There are **two different “histories”**:

1. **UI history** — messages the student sees after refresh (already done).

Scope #3 says: *load earlier messages of a conversation as context when the student continues it.*  
AC2 says: *continuing a conversation lets Pandu use earlier messages (e.g. a follow-up works).*

Saving and showing history ≠ feeding that history into the next Gemini call.

## How “context” is *supposed* to work today

You already built `recall_history`: it can load the last N owned messages (oldest→newest).

But it is only a **tool**. Pandu gets earlier turns only if Gemini decides to call it.

That is unreliable for SCRUM-77:

- System prompt never says “on follow-ups, call `recall_history` first.”
- Pronouns (“that”, “it”, “the second one”) often need prior turns and may not trigger a tool call.
- Even when it does call, you burn a tool step and risk skipping it.

So: **storage is durable; conversational continuity is optional.**

### AI
This helper builds the short chat history that gets stuffed into Pandu’s prompt on every ask.

**What it returns:** a list like `[{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}, ...]`, oldest first.

**Line by line:**

- **`limit=AUTO_HISTORY_LIMIT` (8)** — default window size; callers can pass another limit.
- **`capped = max(1, min(int(limit), MAX_HISTORY_LIMIT))`** — clamp to 1…50 so bad values can’t pull huge history or zero rows.
- **Query** — messages for this conversation only, skip empty `content`, newest first (`-created_at`, `-id`), take the newest `capped` rows.
- **`recent.reverse()`** — flip to oldest → newest so the model sees natural chat order.
- **Loop** — strip whitespace again; skip blanks; keep only `role` + `content` (no ids/citations — prompt needs text, not DB shape).

**Why “before saving the new question”:** if you saved first, this query would include the question you’re about to ask, and Gemini would see it twice.

**Example:** chat has 12 messages → this returns the last 8, chronological. Message 9 (“explain that”) is not in this list yet; the view adds it separately as the current ask.

Right now the helper **does not filter by status**. It only skips empty `content`. So if a `PENDING` or `FAILED` user message has text, it can land in the prompt.

| Status | Role | Meaning |
