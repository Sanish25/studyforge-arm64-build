**3. Keeping large multi-document inputs within the AI limit**
1. **Hard cap before any call** (existing): the total of all selected texts is checked against
   `NOTES_TOTAL_CHAR_LIMIT` (300k). Over the cap → 422. The input is never sampled or silently cut.
2. **Batches** (existing): `_batch_materials` packs materials into batches of ≤ `NOTES_BATCH_CHAR_LIMIT` (60k).

3. **Merge guard** (existing): if the partials together exceed `NOTES_SINGLE_PASS_LIMIT` (200k), it raises
   `LLMError` → 503 instead of overflowing.
4. **New: thin-output ratios vary by detail level.** Today, output under 2% of a batch (or 25% of a merge) is

   The plan sets brief to 0.5% / 10%, keeps standard at 2% / 25%, and sets detailed to 3% / 30%. All

I've recorded A for D1–D6 in the plan. Answers to your questions:

**How will Gemini know the detail level?**
Gemini has no setting for it. The level goes into the system prompt as written instructions with targets the model can count. Only the enum key from the request picks which instruction text is used, so no student text reaches the prompt. Because you chose D4 = A, these targets guide the model but aren't checked, so a "brief" note that comes out a bit long still saves.

**What's the difference between the levels?**

| | brief | standard (today's behaviour) | detailed |
|---|---|---|---|
| Sections | 2–4 main themes | one per topic | one per topic, subtopics split out |
| Per section | at most 3 concepts and 3 points | every definition, rule, value and date | standard, plus examples, conditions and exceptions |
| Concept explanation | 1 sentence | 1–2 sentences | 2–3 sentences |
| Overview | 1–2 sentences | short paragraph | full paragraph |

**Does more detail mean more tokens?**
Yes, but only output tokens. The input is the same source text at every level plus a short instruction (about 200 characters). Output grows roughly like this, as a share of the input text:
- **brief:** about 1–2%
- **standard:** about 5%, which is the level SCRUM-112 measured
- **detailed:** about 8–12%

The brief and detailed figures are my estimates, and I'll measure them. So detailed costs more, takes longer per call, and makes the final merge step's input bigger.

Two plan changes follow from this:
- **The "too short" check will depend on the level.** Otherwise correct brief notes would be rejected and you'd see a 503.
- **I won't cap output tokens.** If Gemini gets cut off at a cap, the response counts as invalid and becomes a 503.

**Is the content the same across formats, just points versus paragraphs?**
The intent is yes. Type and detail decide what's covered, and format decides how each point is written: one short sentence for bullets, 3–5 connected sentences for paragraphs, so paragraphs are longer. Key concepts stay as term and explanation in both formats, and the overview is always prose.

It won't be the same text reflowed, though. Each generation is a separate AI call, so wording, and sometimes which minor facts appear, will differ between a bullets note and a paragraphs note from the same documents.

**3. Keeping large multi-document inputs within the AI limit**
