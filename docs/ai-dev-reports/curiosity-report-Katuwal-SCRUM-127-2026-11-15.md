### STUDENT
What if two workers process the same document and both send results back? How does Django know which one to accept?

### AI
Django doesn’t compare which worker was faster. It uses the **job ID, document ID, source hash, and attempt number** to validate callbacks, then locks the Document and Job rows so concurrent callbacks are handled one at a time ([callback handler](C:/Users/crisu/Desktop/CS3398/studyforge/backend/apps/documents/result_callbacks.py)).

For two workers processing the **same job**:

- An identical result after the first was saved is acknowledged as a duplicate.
- A conflicting result after the job is terminal is rejected; it can’t overwrite the saved result.
- A callback from an older attempt is rejected once Django has recorded a newer attempt.

So the first terminal result Django accepts wins—even if another worker might later produce a different result. These checks protect stored state, but they don’t prevent duplicate processing or guarantee the winning result is the “best” one.
