### Course rename and delete

`PATCH /api/v1/courses/<id>/` and `DELETE` are implemented in `CourseDetailView` in `backend/apps/courses/views.py`, routed in `backend/apps/courses/urls.py`.

Rename validates the submitted name with `CourseRenameSerializer`, trims surrounding whitespace, saves only the name, and returns the updated course. Empty, whitespace-only, missing, non-text, overlong, and control-character names are rejected with HTTP 400. Delete locks the owned course inside a durable transaction; on failure it returns 503, otherwise 204.

Tests in `backend/apps/courses/tests.py` cover rename persistence, invalid names, foreign-course 404s, authentication, and successful deletion. Broader cascade behavior is covered in `backend/tests/documents/test_material_deletion.py`.

### To-do edit and delete

`PATCH` and `DELETE /api/v1/todos/<id>/` are implemented in `TodoDetailView` in `backend/apps/courses/views.py`. The lookup scopes the task through its course owner; foreign and missing tasks both return 404. The update serializer accepts a title and/or completion state, rejects empty updates and invalid titles, and saves only submitted fields. Delete returns 204.

Tests in `backend/apps/courses/tests.py` cover title edits and validation, completion updates, foreign-user access, deletion, and unauthenticated requests.

### Document rename and delete

`PATCH` and `DELETE /api/v1/documents/<id>/` are implemented in `DocumentDetailView` in `backend/apps/documents/views.py`, routed in `backend/apps/documents/urls.py`.

Rename accepts exactly `{"name": ...}`. It trims the name and rejects empty, non-text, overlong, or control-character input. Ownership is checked before the update. Delete calls `delete_material`, which locks the owned document, deletes its database record and related rows in a durable transaction, then removes the source file. Failures produce a 503 response.

`backend/tests/documents/test_material_management.py` covers authentication, private 404 behavior, invalid rename data, and preservation of document fields during rename. `backend/tests/documents/test_scrum79_cleanup.py` covers document rename/delete and foreign-user protection.

### Chunk and related-data deletion

`Chunk.document` has `on_delete=models.CASCADE` in `backend/apps/knowledge/models.py`. Deleting a document cascades to its chunks and jobs; service cleanup also removes the stored source file. Course deletion cascades through documents and other course-owned records. Course deletion additionally removes document files through deletion signals.

Tests assert document deletion removes chunks and embeddings in `test_scrum79_cleanup.py`, while `test_material_deletion.py` checks course deletion removes document chunks, jobs, related course records, and files while preserving unrelated data. The document tests also cover storage and database failure behavior.
